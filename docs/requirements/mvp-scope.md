# MVP 范围说明：集装箱装箱优化器（Packing Optimizer）

## 1. 目标
提供一个最小可用的装箱优化工具：用户输入货物与容器信息，系统通过数学建模/启发式算法输出最优或近似最优装载方案，并支持 3D 展示、手动微调、结果导出。

MVP 的核心判断标准：
- 能在一个页面完成「输入 → 求解 → 查看 → 微调 → 导出」闭环。
- 明确约束与目标函数，输出可复现、可校验、可导出。

## 2. 目标用户
- 计划员/业务人员：需要快速得到装箱方案与装载率
- 仓库/操作人员：需要在 3D 中查看并在必要时微调位置

## 3. 用户主流程（必须闭环）
1) 录入/导入货物（尺寸、重量、数量、约束）
2) 选择容器（标准或自定义）
3) 点击“求解”生成方案（展示评分与告警）
4) 3D 查看方案（定位/高亮某件货物）
5) 必要时手动调整（拖拽/旋转/吸附；碰撞/越界/超重校验）
6) 导出（plan.json + items.csv/xlsx + view.png）

## 4. In Scope（MVP 必做）
- 货物输入：L/W/H、重量、数量（必填）
  - 约束（MVP 最小集）：可旋转（允许的朝向集合）、可堆叠/禁压、优先级（可选）
- 容器输入：内尺寸、载重上限；标准库 + 自定义
- 求解：返回 placements（坐标、朝向、箱号）、评分（装载率等）、warnings/unplaced（如有）
- 3D：旋转/缩放/平移、选中高亮、列表定位
- 手动：拖拽/旋转；碰撞/越界/超重校验
  - 旋转规则：默认仅支持 90° 轴对齐旋转（与装箱算法一致），避免自由旋转带来的物理与碰撞复杂度
  - 吸附（可选实现顺序）：吸附地面、吸附容器壁、吸附相邻箱体边缘
  - 交互必须提供键盘替代路径（见 `docs/ui-lockfiles/manual-editing.md`）
- 导出：plan.json、items.csv（或 xlsx 二选一）、view.png（3D 截图）
  - 推荐一键 ZIP：`plan.json + items.csv + view.png`（导出细则见 specs）

## 5. Out of Scope（MVP 不做）
- 物流链路（询价/比价/委托/跟单/结算/供应商）
- 多组织/审批/复杂权限
- 移动端作业指导/扫码/离线
- 加固工艺、隔板、绑带等高级装载工艺
- 多仓/多站点/多容器协同（后续迭代再评估）

## 6. 非功能要求（MVP 下限）
- 可复现：同输入在相同版本下结果应一致或可解释（随机种子/策略需记录）
- 性能：20–200 件货物在可接受时间内出解（具体阈值在验收文档中定义）；超时应返回“当前最优”并标记为 best-effort
- 可用性：核心操作不超过 1 个页面完成（输入/求解/3D/调整/导出）

## 7. 关键范围取舍（避免“optimalpacking 复杂度”）
- 容器：MVP 支持单容器；多容器仅作为输入结构保留（后端可忽略或逐个求解）。
- 约束：不实现加固工艺、隔板、绑带、重心/倾覆等高级约束。
- 目标：以“体积利用率最大化 + 尽量装入更多件数”为主；不做成本/路线/多目标权重配置器。
- 手动微调：提供基础拖拽/旋转/吸附与校验；不做高级自动对齐、批量规则编辑。
- 算法：采用可解释、可复现的启发式/近似算法作为默认求解器；不承诺全局最优（算法细则见 `docs/specs/packing-algorithm.md`）。
