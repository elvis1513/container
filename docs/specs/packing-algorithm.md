# 装箱算法规格（MVP）

本文件定义 MVP 的求解目标、硬约束、输入输出语义，以及默认启发式算法的实现要点。

## 1. 问题定义
- 输入：一组轴对齐长方体货物（可带数量/约束）与一个容器（轴对齐长方体）。
- 输出：每件货物在容器内的放置位置与朝向（orientation），并给出评分与未装入原因。

## 2. 硬约束（必须满足）
1) **边界约束**：每件货物必须完全位于容器内：
   - `0 <= x <= container.L - item.l`，同理 y/z
2) **非重叠**：任意两件货物在三维空间不相交（允许面贴面接触）。
3) **重量约束**：已装入货物总重量 `<= container.maxWeight`。
4) **旋转约束**：货物只能在允许的朝向集合中旋转（MVP 默认仅 90° 轴对齐旋转）。

> MVP 默认不做“重心/倾覆/绑带/隔板”等高级物理约束；若后续引入，必须新增版本号与向后兼容策略。

## 3. 目标函数（MVP）
综合目标（按优先级排序）：
1) **最大化装入件数**（优先保证尽量装入更多件）
2) **最大化体积利用率**（装入体积 / 容器体积）
3) **最小化最高堆叠高度**（降低不稳定风险，可选项）

评分建议：
- `packedCount`、`volumeUtilization` 为主；`maxZ` 为次。
- 若实现多轮搜索，取最优 score 的方案；平分时以更低 `maxZ`、更低 `y`、更低 `x` 作为稳定 tie-break。

## 4. 默认求解器（启发式）：EMS / Extreme Points
MVP 推荐使用可解释、可复现的启发式算法（不承诺全局最优）。

### 4.1 核心思想
维护一组“可放置的空余空间”（Empty Maximal Spaces, EMS）或“极点”(Extreme Points, EP)：
- 初始空间为整个容器。
- 每放入一件货物后，将被占用空间从候选空间中剔除并分裂出新的空余空间。
- 迭代尝试把下一件货物放入某个空间中。

### 4.2 货物排序（MVP 默认）
- 主排序：体积降序
- 次排序：最长边降序
- 再次排序：重量降序（可选）

### 4.3 放置搜索
对每个货物 item：
1) 遍历候选空间 S（可限制 topK 以控制复杂度）
2) 枚举 item 的允许朝向（orientation 集）
3) 若 `item` 可放入 S：生成候选 placement
4) 选择最优 placement（评分策略见 4.4）

### 4.4 放置评分（建议）
- 先最小化 `z`（尽量贴地放）
- 再最小化 `y`、`x`（形成稳定排列）
- 再最大化“紧密度”（例如 placement 后剩余空间体积更小/或与边界贴合更多）

### 4.5 空间分裂与剪枝
放入 item 后，对被放置空间 S 进行分裂：
- 生成最多 3 个轴对齐剩余空间（沿 x/y/z 方向切分）
- 删除体积为 0 或任一边 < `minDimensionEpsilon` 的空间
- 删除被其他空间完全包含的空间（dominated space pruning）

### 4.6 超时与 best-effort
- 每次求解必须接收 `maxDurationMs`。
- 达到时间上限时立即返回当前最优解，并在结果中标记 `status=TIMEOUT_BEST_EFFORT`。

## 5. 手动微调与校验
- 微调后必须重新校验：边界、非重叠、重量。
- 若启用“稳定性校验”（可选）：
  - 货物底面必须至少满足一定比例的支撑（例如 80% 面积由地面或下层货物承托）。
- 校验结果必须可定位到具体货物（id 列表）。

## 6. 版本与复现
- 结果必须包含：`solverVersion`、`seed`、`options`。
- 相同输入 + 相同版本 + 相同 seed 必须输出一致 placement（允许 warnings 文案差异，但结构必须一致）。
